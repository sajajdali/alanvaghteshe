# راهنمای اعمال دو تغییر روی اپلیکیشن موجود

این فایل فقط دو تغییر لازم روی اپلیکیشن فعلی را توضیح می‌دهد. ساختار صفحه‌ها، طراحی فعلی، مدل‌های دیگر و Navigationهای موجود نباید بازنویسی شوند.

دو تغییر موردنظر:

1. در صفحه نتیجه عضویت، کاربری که پکیج رایگان Onboarding گرفته است نباید دکمه «خرید برنامه» ببیند.
2. متن «رژیم ۱۵ روزه‌ات تمام شد» نباید هنگام دریافت اولین رژیم نمایش داده شود و فقط باید در جریان پایان رژیم قبلی نمایش داده شود.

---

# تغییر اول: دکمه صفحه نتیجه عضویت

## صفحه و API مربوطه

این تغییر مربوط به صفحه‌ای است که در اپ با نام Package Landing، Landing یا BMI Result شناخته می‌شود.

API صفحه:

```http
GET /v1/landing/bmi_result
```

در پاسخ این API کلید جدید زیر اضافه شده است:

```text
onboarding_package
```

کلید قدیمی زیر نیز برای سازگاری با نسخه‌های فعلی اپ همچنان در پاسخ باقی مانده است:

```text
order_diet
```

وجود `order_diet` به‌تنهایی به این معنی نیست که باید دکمه خرید نمایش داده شود. اولویت تصمیم‌گیری همیشه با `onboarding_package` است.

## حالت اول: کاربر پکیج رایگان Onboarding دارد

نمونه بخش مرتبط پاسخ:

```json
{
  "order_diet": {
    "title": "خرید برنامه رژیمی تخصصی",
    "button": "خرید برنامه",
    "description": "همین الان برنامه رژیمی تخصصی خودتون رو بگیرید و بریم برسیم به وزن هدف."
  },
  "onboarding_package": {
    "package_user_id": 10,
    "package_id": 4,
    "title": "پکیج رایگان شما فعال است",
    "button": "ادامه و دریافت رژیم",
    "route": "/new_diet",
    "description": "پکیج رایگان Onboarding برای شما فعال شده است. حالا می‌توانید ادامه دهید و رژیم خود را دریافت کنید."
  }
}
```

وقتی `onboarding_package` یک Object است:

- بلوک `order_diet` در UI نمایش داده نشود.
- عنوان از `onboarding_package.title` خوانده شود.
- توضیحات از `onboarding_package.description` خوانده شود.
- متن دکمه از `onboarding_package.button` خوانده شود.
- با لمس دکمه، مسیر `onboarding_package.route` باز شود.
- در حال حاضر Route برابر `/new_diet` است و باید کاربر را وارد جریان دریافت رژیم کند.
- اپ نباید در این حالت کاربر را به صفحه انتخاب یا خرید پکیج ببرد.

متن‌ها نباید در اپ Hard-code شوند. مقادیر برگشتی API مرجع نمایش هستند.

## حالت دوم: کاربر پکیج رایگان Onboarding ندارد

نمونه بخش مرتبط پاسخ:

```json
{
  "order_diet": {
    "title": "خرید برنامه رژیمی تخصصی",
    "button": "خرید برنامه",
    "description": "همین الان برنامه رژیمی تخصصی خودتون رو بگیرید و بریم برسیم به وزن هدف."
  },
  "onboarding_package": null
}
```

وقتی `onboarding_package` برابر `null` است:

- رفتار فعلی اپ حفظ شود.
- عنوان از `order_diet.title` نمایش داده شود.
- توضیحات از `order_diet.description` نمایش داده شود.
- متن دکمه از `order_diet.button` نمایش داده شود.
- دکمه همان صفحه خرید پکیج فعلی اپ را باز کند.

اگر کلید `onboarding_package` در پاسخ وجود نداشت، برای سازگاری با Backend قدیمی، معادل `null` در نظر گرفته شود.

## شرط نهایی تغییر اول

```dart
final onboardingPackage = response.onboardingPackage;

if (onboardingPackage != null) {
  // عنوان، توضیحات و دکمه از onboarding_package
  // Navigation با onboarding_package.route
  // عدم نمایش خرید برنامه
} else {
  // عنوان، توضیحات و دکمه از order_diet
  // اجرای جریان خرید فعلی اپ
}
```

نباید براساس `package_id` ثابت، متن دکمه یا وجود `order_diet` تصمیم‌گیری شود. تنها شرط معتبر این است:

```dart
response.onboardingPackage != null
```

## نکته مربوط به Cache

بعد از موفقیت درخواست زیر:

```http
POST /v1/onboarding/free-package/activate
```

پاسخ Cacheشده صفحه Landing باید پاک یا Refresh شود. هنگام ورود به صفحه نتیجه، `GET /v1/landing/bmi_result` دوباره فراخوانی شود تا مقدار جدید `onboarding_package` دریافت شود.

# تغییر دوم: نمایش‌ندادن پیام پایان رژیم در رژیم اول

## مشکل فعلی

کاربری که برای اولین بار وارد فرایند دریافت رژیم شده است، در بالای صفحه متن‌هایی شبیه موارد زیر می‌بیند:

```text
رژیم ۱۵ روزه‌ات تمام شد

برای اینکه برنامه غذاییت همیشه متناسب با شرایط و وزن جدیدت باشه، هر ۱۵ روز رژیمت به‌روز می‌شه.

رژیم جدیدت کاملاً رایگانه و هیچ هزینه‌ای نداره.
```

این محتوا مربوط به تمدید یا دریافت رژیم بعدی است و برای کاربری که هنوز اولین رژیمش را نگرفته نباید نمایش داده شود.

عنوان `package` که در AppBar یا بالای این صفحه نمایش داده می‌شود نیز از API دریافت رژیم ارسال نمی‌شود. اگر این عنوان در اپ دیده می‌شود، از Route یا Widget خود اپ آمده و باید متناسب با عنوان فعلی صفحه اصلاح یا حذف شود.

## API صفحه دریافت رژیم

```http
GET /v1/profile/diet_request_and_order/get_information_pages
```

این API اطلاعات فرم دریافت رژیم را برمی‌گرداند، از جمله:

```json
{
  "user": 123,
  "target_page": "new_diet",
  "suggested_plan_id": 1,
  "select_diet_plan": {},
  "get_weight": {},
  "support_page": {}
}
```

این API متن «رژیم ۱۵ روزه‌ات تمام شد» یا بنر پایان رژیم را برنمی‌گرداند. بنابراین این متن نباید به‌صورت ثابت در Widget صفحه `new_diet` یا Package قرار داشته باشد.

## منبع صحیح پیام پایان رژیم

اطلاعات پایان رژیم از Dashboard API می‌آید:

```http
GET /v1/profile/dashboard
```

کلید مربوطه:

```text
popup
```

اگر Backend تشخیص دهد کاربر یک رژیم تمام‌شده دارد، پکیج او فعال است و در حال حاضر رژیم فعال ندارد، `popup` را به‌صورت Object برمی‌گرداند:

```json
{
  "popup": {
    "icon": "...",
    "title": "رژیم شما تمام شده است",
    "description_box": "ساخت رژیم جدید هزینه جداگانه‌ای نداره و می‌تونی دوباره رژیمت رو انتخاب یا تغییر بدی.",
    "body": "رژیم‌های الان وقتشه به‌صورت ۱۵ روزه طراحی می‌شن...",
    "buttons": []
  }
}
```

اگر کاربر اولین رژیمش را هنوز نگرفته باشد، مقدار مورد انتظار این است:

```json
{
  "popup": null
}
```

## رفتار لازم در اپ

برای کاربرِ در حال دریافت اولین رژیم:

- متن پایان رژیم نمایش داده نشود.
- بنر تمدید رژیم نمایش داده نشود.
- متن «رژیم جدیدت رایگانه» نمایش داده نشود.
- صفحه مستقیماً محتوای عادی اولین دریافت رژیم را نمایش دهد.
- هیچ تصمیمی براساس متن Hard-codeشده یا State قدیمی کاربر گرفته نشود.

برای کاربری که رژیم قبلی او تمام شده است:

- پیام پایان رژیم فقط وقتی نمایش داده شود که `profile/dashboard.popup` یک Object معتبر باشد.
- `title` از `popup.title` خوانده شود.
- متن اصلی از `popup.body` خوانده شود.
- متن توضیحی از `popup.description_box` خوانده شود.
- دکمه‌ها از `popup.buttons` ساخته شوند.
- متن Popup داخل اپ Hard-code نشود.

## شرط نهایی تغییر دوم

```dart
final popup = dashboardResponse.popup;

if (popup != null) {
  showPopupFromApi(
    title: popup.title,
    body: popup.body,
    description: popup.descriptionBox,
    buttons: popup.buttons,
  );
}
```

در Widget صفحه دریافت رژیم نباید چنین منطق ثابتی وجود داشته باشد:

```dart
// اشتباه
Text('رژیم ۱۵ روزه‌ات تمام شد');
```

همچنین نباید صرفاً با ورود به Route دریافت رژیم، پیام پایان رژیم نمایش داده شود:

```dart
// اشتباه
if (currentRoute == '/new_diet') {
  showDietFinishedBanner();
}
```

نمایش این پیام فقط به مقدار `popup` در پاسخ Dashboard وابسته است.

## جلوگیری از نمایش State قدیمی

هنگام ورود کاربر به جریان دریافت رژیم:

- Popup ذخیره‌شده مربوط به کاربر قبلی استفاده نشود.
- بعد از Logout، State مربوط به Dashboard و Popup پاک شود.
- هنگام تغییر حساب، Dashboard برای کاربر جدید مجدداً دریافت شود.
- در صورت Refresh صفحه، مقدار جدید `popup` جایگزین مقدار قبلی شود.
- در زمان Loading، بنر پایان رژیم به‌صورت پیش‌فرض نمایش داده نشود.

# خلاصه تغییرات لازم

## صفحه نتیجه عضویت

```text
onboarding_package != null
    → نمایش «ادامه و دریافت رژیم» از اطلاعات onboarding_package
    → عدم نمایش خرید برنامه

onboarding_package == null
    → نمایش اطلاعات order_diet
    → اجرای جریان خرید فعلی
```

## صفحه دریافت رژیم

```text
dashboard.popup != null
    → نمایش Popup پایان رژیم از اطلاعات API

dashboard.popup == null
    → عدم نمایش هرگونه متن پایان رژیم
```

# تست‌های تحویل

## تست تغییر اول

1. کاربری که پکیج رایگان Onboarding را فعال کرده وارد Landing شود.
2. فقط دکمه «ادامه و دریافت رژیم» دیده شود.
3. متن یا دکمه «خرید برنامه» دیده نشود.
4. دکمه، Route برگشتی `onboarding_package.route` را باز کند.
5. کاربری که پکیج Onboarding ندارد همان جریان خرید قبلی را ببیند.

## تست تغییر دوم

1. کاربری که هنوز هیچ رژیمی نگرفته وارد دریافت رژیم شود.
2. متن «رژیم ۱۵ روزه‌ات تمام شد» نمایش داده نشود.
3. عنوان ثابت `package` در بالای صفحه نمایش داده نشود، مگر اینکه عنوان مورد تأیید طراحی فعلی اپ باشد.
4. کاربری که رژیم قبلی او تمام شده و `dashboard.popup` دارد، Popup پایان رژیم را ببیند.
5. متن Popup از API خوانده شود و Hard-code نباشد.
6. وقتی `dashboard.popup` برابر `null` است، هیچ بنر یا Popup پایان رژیمی نمایش داده نشود.
