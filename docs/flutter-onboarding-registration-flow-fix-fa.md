# اصلاح جریان Onboarding و پایان ثبت‌نام در اپلیکیشن Flutter

## هدف تغییر

این تغییر فقط مربوط به مسیریابی اپلیکیشن Flutter است. صفحه Onboarding اکنون در محل درست، یعنی بعد از تأیید کد ورود و قبل از فرم نام و نام خانوادگی، نمایش داده می‌شود و این رفتار باید حفظ شود.

مشکل فعلی این است که بعد از تکمیل مراحل عضویت، Onboarding دوباره نمایش داده می‌شود و صفحه قدیمی «در حال ایجاد برنامه» و پیام موفقیت حذف شده است. رفتار صحیح در این سند مشخص شده است.

## خلاصه رفتار صحیح

```text
ورود با شماره موبایل و تأیید کد
  ├─ کاربر جدید + Onboarding فعال → نمایش Onboarding فقط یک‌بار
  │                                  سپس فرم نام و نام خانوادگی و مراحل عضویت
  ├─ کاربر جدید + Onboarding غیرفعال → فرم نام و نام خانوادگی و مراحل عضویت
  └─ کاربر قدیمی                     → ادامه مسیر معمول کاربر قدیمی

تکمیل آخرین مرحله عضویت
  → نمایش Progressbar «برنامه شما در حال ایجاد است»
  → نمایش بخش «مسیر موفقیت از اینجا شروع می‌شود»
  → عدم نمایش متن شارژ ۲۰ هزار تومانی کیف پول
  → ادامه مسیر قبلی اپلیکیشن
```

## ۱. محل مجاز نمایش Onboarding

Onboarding فقط در نقطه ورود کاربر جدید نمایش داده شود:

1. کاربر شماره موبایل را وارد می‌کند.
2. کد تأیید با موفقیت Verify می‌شود.
3. اپ پاسخ Verify را بررسی می‌کند.
4. اگر کاربر جدید است و `show_onboarding` برابر `true` یا `next_route` برابر `/onboarding` است، Onboarding نمایش داده شود.
5. بعد از اتمام یا ردکردن Onboarding، اپ با استفاده از `continue_route` وارد فرم نام و نام خانوادگی و ادامه مراحل عضویت شود؛ این مسیر معمولاً `/statement` است.

نمونه فیلدهای مرتبط در پاسخ Verify:

```json
{
  "is_old_user": false,
  "show_onboarding": true,
  "next_route": "/onboarding",
  "continue_route": "/statement"
}
```

شرط پیشنهادی:

```dart
final shouldShowOnboarding =
    response.isOldUser == false &&
    onboardingHasNotBeenHandled &&
    (response.showOnboarding == true ||
     response.nextRoute == '/onboarding');
```

نام متغیرها نمونه است و باید با معماری فعلی اپ تطبیق داده شود.

## ۲. جلوگیری از نمایش دوباره Onboarding

به محض اینکه کاربر Onboarding را تمام یا رد کرد، وضعیت آن برای همان کاربر ثبت شود. کلید ذخیره‌شده باید به شناسه کاربر وابسته باشد تا تعویض حساب باعث اختلال نشود؛ برای مثال:

```text
onboarding_handled_{userId} = true
```

در ادامه همان ثبت‌نام، Onboarding تحت هیچ شرایطی دوباره باز نشود. به‌خصوص:

- هنگام ورود به فرم نام و نام خانوادگی؛
- هنگام جابه‌جایی بین مراحل عضویت؛
- بعد از ارسال `complete_register`؛
- هنگام نمایش Progressbar ساخت برنامه؛
- هنگام بازسازی Widget، تغییر Route یا بازگشت از پس‌زمینه.

اگر اپ وضعیت را فقط در حافظه نگه دارد، با بسته و بازشدن اپ احتمال نمایش مجدد وجود دارد؛ بنابراین از فضای ماندگار اپ مانند SharedPreferences یا storage فعلی پروژه و یک کلید وابسته به `userId` استفاده شود.

نکته مهم: در نسخه فعلی Backend ممکن است پاسخ `POST /v1/complete_register` نیز به دلیل تنظیم فعال Onboarding، مقدار `next_route: "/onboarding"` برگرداند. اپ پس از تکمیل عضویت نباید با دیدن این مقدار Onboarding را دوباره نمایش دهد. تصمیم نمایش Onboarding فقط در جریان Verify کاربر جدید گرفته شود.

## ۳. رفتار بعد از تکمیل عضویت

پس از موفقیت درخواست زیر:

```http
POST /v1/complete_register
Authorization: Bearer {token}
```

اپ باید جریان قدیمی پایان ثبت‌نام را اجرا کند و به صفحه Onboarding برنگردد:

1. Progressbar قبلی نمایش داده شود.
2. متن مربوط به آماده‌سازی برنامه، مانند «برنامه شما در حال ایجاد است»، نمایش داده شود.
3. بخش قبلی با پیام «مسیر موفقیت از اینجا شروع می‌شود» نمایش داده شود.
4. سایر اجزا، انیمیشن‌ها و ادامه مسیر قبلی این صفحه حفظ شوند.
5. فقط پیام مربوط به شارژ کیف پول حذف شود.

متنی که نباید نمایش داده شود:

```text
کیف پول شما ۲۰ هزار تومان شارژ شد
```

اگر مبلغ این متن به‌صورت پویا از API یا تنظیمات دریافت می‌شود، کل بلوک رابط کاربری مربوط به پیام شارژ کیف پول مخفی/حذف شود؛ صرفاً عدد `۲۰ هزار تومان` حذف نشود.

این تغییر فقط نمایشی است و نباید منطق Backend کیف پول، موجودی کاربر یا درخواست تکمیل ثبت‌نام را تغییر دهد.

## ۴. اولویت مسیریابی در Flutter

برای جلوگیری از تداخل Routeها، این ترتیب رعایت شود:

### بعد از Verify

```text
اگر کاربر جدید است و Onboarding فعال است و قبلاً مدیریت نشده:
    Onboarding
وگرنه اگر ثبت‌نام ناقص است:
    فرم نام و نام خانوادگی / statement
وگرنه:
    مسیر معمول کاربر قدیمی
```

### بعد از complete_register

```text
اگر درخواست موفق بود:
    وضعیت ثبت‌نام را کامل در نظر بگیر
    پاسخ /onboarding را نادیده بگیر
    Progressbar ساخت برنامه را نمایش بده
    پیام «مسیر موفقیت از اینجا شروع می‌شود» را نمایش بده
    بلوک پیام شارژ کیف پول را نمایش نده
```

برای جابه‌جایی از Onboarding به فرم ثبت‌نام و از آخرین مرحله عضویت به صفحه ساخت برنامه، Routeهای قبلی از stack حذف یا جایگزین شوند تا دکمه Back باعث برگشت به Onboarding نشود.

## ۵. مواردی که نباید تغییر کنند

- طراحی و محتوای فعلی Onboarding که از API دریافت می‌شود؛
- شرط فعال یا غیرفعال بودن Onboarding در پنل؛
- نمایش Onboarding قبل از فرم نام و نام خانوادگی؛
- مراحل و سؤال‌های فعلی عضویت؛
- منطق ساخت برنامه و Progressbar قبلی؛
- عملیات واقعی شارژ کیف پول در Backend، در صورت وجود.

## ۶. معیارهای پذیرش

- کاربر جدید و Onboarding فعال: Onboarding دقیقاً یک‌بار و بعد از Verify نمایش داده می‌شود.
- بعد از Onboarding، فرم نام و نام خانوادگی باز می‌شود.
- کاربر جدید و Onboarding غیرفعال: مستقیماً فرم نام و نام خانوادگی باز می‌شود.
- کاربر قدیمی: Onboarding مربوط به ثبت‌نام جدید نمایش داده نمی‌شود.
- بعد از تکمیل مراحل عضویت، Onboarding دوباره نمایش داده نمی‌شود؛ حتی اگر پاسخ `complete_register` مسیر `/onboarding` داشته باشد.
- بعد از تکمیل عضویت، Progressbar «برنامه شما در حال ایجاد است» نمایش داده می‌شود.
- بخش «مسیر موفقیت از اینجا شروع می‌شود» نمایش داده می‌شود.
- متن یا بلوک «کیف پول شما ۲۰ هزار تومان شارژ شد» نمایش داده نمی‌شود.
- دکمه Back از صفحه پایان عضویت، کاربر را به Onboarding برنمی‌گرداند.
- بسته و بازکردن اپ در ادامه همان ثبت‌نام باعث نمایش مجدد Onboarding نمی‌شود.

## ۷. سناریوی تست نهایی

1. Onboarding را در پنل فعال کنید.
2. با شماره‌ای که کاربر جدید محسوب می‌شود وارد شوید.
3. کد تأیید را وارد کنید؛ Onboarding باید باز شود.
4. Onboarding را تمام یا رد کنید؛ فرم نام و نام خانوادگی باید باز شود.
5. تمام مراحل عضویت را تکمیل کنید؛ Onboarding نباید دوباره باز شود.
6. Progressbar آماده‌سازی برنامه باید ظاهر شود.
7. بخش «مسیر موفقیت از اینجا شروع می‌شود» باید دیده شود.
8. هیچ متن یا کارت مربوط به «شارژ ۲۰ هزار تومان کیف پول» نباید دیده شود.
9. همین تست را با Onboarding غیرفعال تکرار کنید؛ مرحله Onboarding باید حذف شود، اما صفحه پایان عضویت و Progressbar همچنان نمایش داده شوند.
